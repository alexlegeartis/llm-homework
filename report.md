## Корпус и формулы

Использован весь учебник Горяйнова и Половинкина, 2025: 147 страниц PDF, 526 фрагментов. PDF и корпус закреплены SHA-256 в `corpus_manifest.json`. Данные подготовлены самостоятельно: преподаватель уточнил, что перечисленные в условии готовые файлы фактически не выдавались.

PyMuPDF даёт символы, шрифты и координаты. Кириллица в части TeX-шрифтов декодируется из cp1251; математические шрифты приводятся к Unicode. Горизонтальные линии и положения символов позволяют восстановить дроби как `(числитель)/(знаменатель)`, надчёркивание как `bar(z)`, степени и индексы как `^{...}` и `_{...}`. Например, сохранены `∂f/∂bar(z)=0` и множитель `n!/(2πi)` со знаменателем `(ζ−z)^{n+1}`. Эти места проверены по PDF и тестом. Генеративная модель при подготовке данных не используется.

Объединяются абзацы одной страницы до примерно 850 символов; заголовки теорем и определений начинают новый фрагмент. Максимум — 1500 символов. ID содержит номер страницы PDF и порядковый номер фрагмента. Геометрическое восстановление формул остаётся эвристикой: сложные многострочные выражения могут содержать артефакты. Страничная граница иногда разделяет условие и продолжение теоремы.

## Поиск, контекст и генерация

Baseline: BM25, один поиск по вопросу со всеми вариантами, один вызов Qwen. Итоговая цепочка: Qwen переписывает вопрос в короткий поисковый запрос; BM25 и CPU-эмбеддер multilingual-e5-small дают по 18 кандидатов; RRF с константой 60 выбирает шесть. E5 — 118 млн параметров, ONNX int8, фиксированная ревизия; используются усреднение по маске, нормализация и префиксы `query:` / `passage:`.

В контекст попадают целые фрагменты с исходными ID, страницей и разделом. UTF-8-оценка сверху резервирует 512 выходных токенов при лимите 8192 на запрос; фактический расход проверяется по `usage` API. Сборка индекса, загрузка весов и прогрев учитываются отдельно; поиск включён в `elapsed_ms` вопроса. Второй вызов Qwen выдаёт JSON по схеме. Код проверяет фактические ID вариантов, уникальность ссылок, длину обоснования и согласованность отказа с пустыми списками. При технической ошибке trace содержит причину; такая запись получает ноль.

Отказ запрашивается только при недостаточности сведений. Он не исправляет ошибку поиска: если нужная теорема существует, пропуск считается ошибкой. Цепочка фиксированная, без адаптивного цикла и повторных попыток; обычный итоговый вопрос использует два вызова. Rewrite служит только поиску, его текст не подменяет свидетельства из учебника.

Все генеративные шаги выполняет Qwen3.5-4B Q4_K_M, веса закреплены ревизией GGUF и SHA-256. Во всех экспериментах одинаковы temperature=0, top_p=1, seed=42, max_tokens=512, thinking выключен. Обучения, генеративного обогащения корпуса и переноса диалога между вопросами нет. При предсказании сеть используется только для LLM endpoint; все запросы содержат обязательные заголовки.

## Эксперименты

Во всех прогонах одни и те же 15 вопросов. Accuracy — точное совпадение набора вариантов с учётом отказа; Q — среднее четырёх средних по категориям с F1 ссылок. Таблица содержит автоматическую оценку по подготовленным эталонам; содержательные проблемы обоснований разобраны ниже.

| Конфигурация | Accuracy | Q | Вход | Выход | Вызовы | C | Медиана, с |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Без контекста | 0,733 | — | 226,1 | 119,2 | 1 | 958,9 | 22,9 |
| BM25 baseline | 0,667 | 0,630 | 1409,2 | 155,7 | 1 | 2287,9 | 50,7 |
| Итоговая система | 0,667 | 0,615 | 1713,2 | 192,3 | 2 | 2994,5 | 55,1 |

| Без rewriting | 0,733 | 0,701 | 1601,3 | 164,5 | 1 | 2515,2 | 44,2 |

Итоговая система дала те же 10/15 точных ответов, что baseline, но хуже ссылки и распределение ошибок по категориям. Средняя стоимость выросла на 30,9%. Более сложный поиск не окупился на этом наборе. Один ответ нарушил согласованность полей JSON и получил технический отказ с нулём за вопрос; его расход API сохранён.

Отключение dense повысило Q на 0,0625: исправились q_001 и q_013, но ухудшился q_010. Dense добавлял фрагменты из поздних глав с похожими словами, не обязательно нужные для вопроса. Удаление этого компонента повысило качество и немного уменьшило токенный контекст.

Отключение rewriting повысило Q на 0,0858 и снизило C на 16,0%: исправились q_012 и q_013, но ухудшился q_006. Сжатый запрос терял существенные условия и иногда менял язык терминов. Лучший локальный результат дал гибридный поиск по исходному вопросу и вариантам с одним вызовом; его конфигурация сохранена в `experiments/without_rewrite/config.json`. Вывод ограничен 15 вопросами: обе проверенные надстройки в полной цепочке оказались неудачными, хотя отдельные ответы улучшались.

Официальный baseline и C_ref не были предоставлены. Для локального сравнения использовано измеренное C_ref=2287,87. У итоговой системы E=0,764 и локальная формула даёт 57,86 против 62,96 у baseline; это не официальный балл. Все вызовы и токены проверяемы по API, превышений лимитов нет. Полные числа и отдельные прогоны сохранены в `experiments.csv` и `experiments/`.

## Три ошибки итогового прогона

1. **q_001, условия комплексной дифференцируемости.** Найдены `p0011_b002` и `p0012_b001`; модель выбрала A, B, C вместо B, C. Нужная теорема была в контексте, но модель не различила существование частных производных и вещественную дифференцируемость. Модель неверно применила найденное условие теоремы.
2. **q_002, производные по z и bar(z).** В контекст попал `p0079_b002` из раздела конформных отображений, а не определяющая формула `p0012_b002`. Получены A, C, D вместо A, C. Проверка страницы 79 показала, что широкое надчёркивание над всем `f(z)` потерялось при извлечении; противоположное условие стало выглядеть как условие для самой f. Ошибка объединяет неудачный rewrite, поиск и повреждение формулы. Поддержка одиночного `bar(z)` не гарантирует восстановления надчёркиваний над выражениями.
3. **q_004, первообразная 1/z.** Варианты B, C выбраны верно, но ссылки — `p0053_b003` и `p0035_b003`. Первый фрагмент определяет вычет, а модель приписывает ему готовое вычисление интеграла 2πi; второй относится к доказательству Морера. Нужные прямые свидетельства `p0031_b002` и `p0028_b003` пропущены. Это пример правильных вариантов со слабо подтверждённым обоснованием; проверка только вариантов скрывает проблему.

## Ресурсы и проверка воспроизводимости

Windows 10, AMD Ryzen 7 5800H, 8 физических / 16 логических ядер, 13,86 ГиБ RAM, Python 3.11.15. GPU не используется. llama.cpp b11669 работает отдельным процессом с восемью потоками и контекстом 8192.

Сборка индекса заняла 132,4 с, пиковая RAM процесса — 691,7 МиБ; индекс вместе с копией CPU-эмбеддера — 130,6 МиБ. Пик RAM предиктора — 521,9 МиБ, отдельного процесса LLM — 3,17 ГиБ. Повторная сборка из другой папки с путями, содержащими пробелы, заняла 163,3 с на фоне работы LLM. `index.json`, векторы и файлы эмбеддера совпали побайтово. Повторная подготовка корпуса, вопросов и эталонов также дала идентичные файлы.

Закреплённые зависимости установлены в отдельное чистое окружение Python 3.11. Восемь тестов проверяют формулы, произвольные ID вариантов, точное совпадение наборов, правила отказа, бюджет контекста, заголовки и сохранение возвращённого API расхода через заглушку. Для LLM варианты обозначаются A–F по текущему порядку, затем метки переводятся в исходные ID; на dev это тождественное отображение. Дополнительный реальный запуск из другой папки с новым ID и перемешанными вариантами вернул правильный коэффициент 24/3!=4 под исходным ID `v_12` и ссылку `p0036_b001`. Ошибка формата обнуляет вопрос; эффективность всего прогона обнуляется при нарушении вычислительного лимита или непроверяемом расходе.
