# ДЗ 1. Доказательный RAG по ТФКП

Кравацкий Алексей Юрьевич, М05-602а.

## Данные и метод

Использован весь учебник Горяйнова и Половинкина: 147 страниц, 526 фрагментов. Корпус и наборы вопросов созданы кодом из PDF и исходных QA. Дополнительно составлены восемь вопросов с эталонами, по два на категорию.

Решение состоит из четырёх шагов:

1. **Извлечение текста.** PyMuPDF читает символы и их координаты. Дроби записываются как `(a)/(b)`, сопряжение — `bar(z)`, корни — `root(n,...)`; сохраняются степени и индексы. Абзацы объединяются в пределах страницы: цель 850, максимум 1500 символов. Каждому фрагменту присваивается воспроизводимый ID. Сложные формулы могут извлекаться с ошибками.
2. **Поиск.** BM25 ранжирует фрагменты по совпадению слов с вопросом и вариантами ответа. Русские слова приводятся к основам, математические обозначения нормализуются. Вес чисел уменьшен до 0.15. Ручной словарь добавляет связанные термины, например название формулы Коши. Готовых ответов и ID вопросов в словаре нет.
3. **Контекст.** Берутся до четырёх основных фрагментов, затем добавляются до двух следующих продолжений того же раздела. Новая теорема, определение, замечание или доказательство останавливают добавление. Ссылка на номер формулы добавляет блок с первым вхождением этого номера. Весь запрос укладывается в 2200 входных токенов.
4. **Ответ.** Один вызов Qwen3.5-4B выбирает варианты, даёт обоснование и ссылки. JSON Schema ограничивает допустимые ID и длину обоснования. При недостаточности исходных сведений модель отказывается, оставляя списки пустыми. Пропуск нужной теоремы поиском считается ошибкой.

Обработка ответа восстанавливает JSON-экранирование LaTeX и удаляет отдельные предложения только о невыбранных вариантах. Исходный текст сохраняется в trace. Это общее правило для всех конфигураций, без обращения к эталонам. В trace также записываются найденные блоки, вызовы и фактический расход API.

Embedding-модели и reranker не используются. Индекс строится без LLM, диалог между вопросами не переносится.

## Эксперименты

Все прогоны используют одинаковые 15 вопросов и параметры Qwen3.5-4B Q8_0 из `runtime.json`. Ревизии закреплены. Бюджет thinking — 3072 токена, общий выход — 4096. Baseline получает три блока после одного BM25-поиска. Итоговая система и две абляции используют тот же промпт baseline.

| Конфигурация | Точные ответы | Q | Стоимость C |
| --- | ---: | ---: | ---: |
| Без контекста | 15/15 | — | 12809.6 |
| Baseline | 11/15 | 0.6950 | 14271.3 |
| Итоговая | 15/15 | 0.9811 | 14818.1 |
| Без продолжений и ссылок на формулы | 15/15 | 0.9704 | 14495.3 |
| Без расширения запросов | 13/15 | 0.8096 | 14890.8 |

Q учитывает правильность ответа и ссылок с усреднением по четырём категориям. Стоимость: `C = входные токены + 4 × выходные токены + 256 × вызовы`, в среднем на вопрос.

- **Расширение запросов:** отключение снижает Q на 0.1715. Например, в №7 обычный поиск находит вычеты, а словарь помогает найти формулу Коши для производных.
- **Продолжения и ссылки:** отключение снижает Q на 0.0107 при сохранении 15/15 наборов. В №7 блок p0035_b001 отсылает к формуле (5.2); расширение добавляет её из p0034_b002.

Без контекста модель тоже выбрала все варианты правильно, но ссылки на учебник отсутствуют. В итоговом RAG потери связаны с лишними или неполными ссылками. Локальная оценка — 97.21/100 относительно собственного baseline. Официальный C_ref не предоставлен, поэтому это не балл закрытого теста. Обоснования проверены отдельно.

## Три ошибки и их причины

1. **Baseline, №4.** Найдены p0031_b002, p0042_b003, p0028_b001. Выбран B вместо B,C: формула интеграла осталась в продолжении p0028_b003. Добавление продолжения исправляет ответ.
2. **Baseline, №5.** Найдены p0031_b002, p0028_b001, p0042_b003. Выбраны A,C вместо A,B: пропущена теорема об исключительной точке. Итоговый поиск находит её в p0030_b003 и получает A,B.
3. **Исходный итоговый ответ, №2.** Найдено определение p0012_b002, правильно выбраны A,C. Дополнительная фраза неверно утверждала постоянство при f_z=0. Её удаляет общее правило обработки невыбранных вариантов; исходник сохранён в trace. Правило ограничено шаблоном и не проверяет математику.

## Ресурсы и воспроизводимость

Полный прогон выполнен 1 ноября 2026 на Colab Tesla T4 (15360 МиБ VRAM), Python 3.11.15, llama.cpp b11669. Поиск работает на CPU, модель — отдельным процессом на GPU. Локальные проверки: Windows 10, Ryzen 7 5800H, 8 физических / 16 логических ядер, 13.86 ГиБ RAM.

Сборка индекса: 0.788 с, пиковая RAM 29.93 МиБ, размер 12.94 МиБ с токенизатором. RAM итогового клиента и поиска — 152.84 МиБ, без LLM. Медианная задержка ответа в параллельном эксперименте — 195.3 с.

Все 75 ответов получены с одним вызовом на вопрос, без технических ошибок и нарушений лимитов. Максимальный вход — 1982 токена, выход — 3272, вход плюс разрешённый выход — 6078. Общая обработка изменила три обоснования; ручных исправлений ответов не было.

Пройдены 14 тестов и запуск из другой папки с новым индексом и шестью перемешанными ID. Чистая пересборка 4 ноября воспроизвела данные и индекс побайтово. Команды находятся в README, хеши данных — в `corpus_manifest.json`, измерения и хеши кода — в `run_metadata.json`.
