## Данные и метод

Использован [учебник по ТФКП](homework_01_rag/materials/homework_01_rag.md#1-материалы). Текст учебника и набор проверочных вопросов собирает [prepare_data.py](homework_01_rag/prepare_data.py#L82) из PDF и [исходных вопросов с ответами](homework_01_rag/materials/tfkp_15_qa.md). Подготовленные мною [восемь вопросов](own_questions.jsonl) и [правильные ответы с подтверждающими фрагментами](own_gold.jsonl) описаны в [own_dataset()](homework_01_rag/prepare_data.py#L59).

Решение состоит из четырёх шагов:

1. **Извлечение текста.** В [page_paragraphs()](homework_01_rag/pdf_text.py#L80) PyMuPDF читает символы и их координаты. Наш код восстанавливает формулы по расположению символов и линий. Дроби записываются как `(a)/(b)`, сопряжение как `bar(z)`, корни как `root(n,...)`. Сохраняются степени и индексы. [extract_corpus()](homework_01_rag/pdf_text.py#L149) объединяет абзацы в пределах страницы, стремясь к 850 символам при максимуме 1500. Фрагментам присваиваются воспроизводимые идентификаторы. Например, `p0012_b002` означает второй фрагмент страницы 12 PDF: `p` обозначает страницу, `b` обозначает фрагмент. [Тест формул](tests/test_homework.py#L163) проверяет дроби, сопряжение, факториалы и корни на страницах 12, 18, 34 и 79 PDF.
2. **Поиск.** [BM25](homework_01_rag/retrieval.py#L105) ранжирует фрагменты по совпадению слов с вопросом и вариантами ответа. Русские слова приводятся к основам, математические обозначения нормализуются. Вес чисел уменьшен до 0.15. Я составил [словарь](homework_01_rag/retrieval.py#L28), который по словам вопроса и вариантов ответа добавляет в поисковый запрос связанные математические термины. Например, запрос о вычислении интеграла дополняется словами «интегральная формула Коши для производных».
3. **Контекст.** Для подготовки ответа [retrieve()](homework_01_rag/retrieval.py#L117) выбирает до четырёх основных фрагментов учебника. К каждому наш алгоритм добавляет до двух следующих фрагментов того же раздела на той же или следующей странице. Добавляются целые фрагменты, которые могут содержать несколько предложений. Если следующий фрагмент начинается с новой теоремы, леммы, следствия, определения, замечания или доказательства, алгоритм не включает его и прекращает добавление соседей. Если в найденном фрагменте упоминается номер формулы, алгоритм также добавляет фрагмент с первым вхождением этого номера в учебнике. В [make_messages()](homework_01_rag/predict.py#L25) к вопросу и вариантам ответа добавляются инструкции для модели и найденные фрагменты с их идентификаторами, страницами и разделами. Фрагменты добавляются целиком и по очереди. Токенизатор Qwen оценивает размер запроса с резервом для шаблона чата. Если добавление очередного фрагмента приведёт к превышению 2200 входных токенов, этот фрагмент пропускается.
4. **Ответ.** Для каждого вопроса выполняется один [вызов Qwen3.5-4B](homework_01_rag/predict.py#L112). Модель получает вопрос, варианты ответа и фрагменты учебника, найденные через BM25 и дополненные по описанным выше правилам. По ним она выбирает верные варианты, пишет обоснование и указывает подтверждающие фрагменты. [JSON Schema](homework_01_rag/predict.py#L43) задаёт формат ответа. В `answer_ids` разрешены только варианты из вопроса, в `citations` допускаются до четырёх идентификаторов фрагментов, переданных модели. Поле `rationale` содержит обоснование до 350 символов. При недостаточности исходных сведений модель возвращает `abstain: true`, оставляет `answer_ids` и `citations` пустыми и указывает причину отказа в `rationale`.

Если модель записывает команды `\bar` или `\frac` в JSON с одним обратным слешем вместо двух, при чтении начало команды превращается в служебный символ. [Код обработки ответа](homework_01_rag/predict.py#L133) восстанавливает исходную запись сопряжения и дробей. Затем [trim_rationale()](homework_01_rag/predict.py#L57) сокращает обоснование по упомянутым буквам вариантов. Например, при выбранных A,C из текста «Верны A и C по формуле. Варианты B и D означают постоянную функцию» удаляется второе предложение. При сокращении исходный текст сохраняется в поле `rationale_before_filter` отладочного файла [dev_trace.jsonl](dev_trace.jsonl). Там также записываются найденные фрагменты, число обращений к Qwen и количество входных и выходных токенов. Поле [elapsed_ms](homework_01_rag/predict.py#L196) содержит время обработки каждого вопроса в миллисекундах, включая поиск и ожидание ответа модели.

## Эксперименты

[run_experiments.py](homework_01_rag/run_experiments.py#L24) сравнивает на [15 вопросах из условия](dev_questions.jsonl) три способа ответа:

- **Без контекста.** Qwen получает только вопрос и варианты ответа.
- **Один поиск BM25.** По тексту вопроса и вариантов ответа BM25 выбирает до трёх фрагментов. Они передаются Qwen для ответа за один вызов. Словарь и добавление соседних фрагментов отключены.
- **С расширением запросов и контекста.** Это RAG из раздела «Данные и метод» с настройками [config.json](config.json): словарь, до четырёх основных фрагментов, добавление соседних фрагментов и фрагментов по номерам формул.

В двух дополнительных экспериментах у последнего варианта отдельно отключаются словарь и добавление фрагментов.

В [runtime.json](runtime.json) для Qwen3.5-4B Q8_0 заданы `thinking_budget_tokens=3072` для рассуждений и `max_tokens=4096` для всего ответа, включая рассуждения. [Клиент](homework_01_rag/predict.py#L112) передаёт эти параметры в API Qwen.

| [Без контекста](experiments/no_context/) | 15/15 | Не оценивается | 12809.6 |

[Оценка Q](homework_01_rag/evaluate.py#L19) учитывает правильность ответа и ссылок с усреднением по четырём категориям. Стоимость рассчитывается как `C = входные токены + 4 × выходные токены + 256 × вызовы`, в среднем на вопрос.

- **Расширение запросов.** Отключение словаря расширения запросов снижает Q на 0.1715. Например, в вопросе №7 обычный поиск находит вычеты, а словарь помогает найти формулу Коши для производных.
- **Продолжения и ссылки.** Отключение добавления соседних фрагментов и переходов по номерам формул снижает Q на 0.0107. Выбор вариантов остаётся правильным во всех 15 вопросах. В вопросе №7 фрагмент `p0035_b001` с замечанием 5.1 отсылает к формуле (5.2). Расширение добавляет саму формулу Коши для производных из фрагмента `p0034_b002`.

На 15 вопросах из условия RAG с расширением теряет баллы на лишних или неполных ссылках. Локальная оценка 97.21/100 использует стоимость нашего варианта с одним поиском BM25. Официальный балл зависит от закрытого теста и C_ref проверяющих.

Словарь составлялся и проверялся на 15 вопросах из условия, поэтому его выигрыш на них может быть завышен из-за подгонки. ## Разбор ошибок в ответах Qwen

Приведены ошибка выбора вариантов на вопросе из условия и две ошибки на своих вопросах. Ссылки ведут к ответам и отладочным файлам с найденными фрагментами.

1. **[Первообразная и интеграл функции `1/z`, вопрос №4 из условия](experiments/baseline/trace.jsonl#L4).** При одном поиске BM25 найдены фрагменты `p0031_b002`, `p0042_b003`, `p0028_b001`. [Выбран B](experiments/baseline/answers.jsonl#L4) вместо B,C. Поиск пропустил формулу интеграла по положительно ориентированной окружности из фрагмента `p0028_b003`. В RAG с расширением этот фрагмент попадает в контекст, и Qwen выбирает B,C.
2. **[Отказ при неизвестной производной, `own_008`](experiments/own_final/answers.jsonl#L8).** Для интеграла `∮ f(z)/z² dz` модель выбрала A,B,C,D вместо отказа. Формула `2πi f′(0)` не определяет число без значения `f′(0)`. В [контексте](experiments/own_final/trace.jsonl#L8) находились `p0042_b003`, `p0070_b001`, `p0070_b002`, `p0070_b003`, `p0040_b001`. Без словаря переданы те же фрагменты, но Qwen [корректно отказалась](experiments/own_without_expansion/answers.jsonl#L8). Причина ошибки в том, что модель подменила недостаточность данных выбором всех возможных значений.
3. **[Неверная формула в обосновании, `own_006`](experiments/own_final/answers.jsonl#L6).** Для интеграла `∮ e^z/z⁴ dz` верно выбран A, то есть `πi/3`. В [контекст](experiments/own_final/trace.jsonl#L6) вошли фрагменты `p0034_b002` с формулой Коши и `p0020_b001`, `p0020_b002` об экспоненте. Несмотря на правильную формулу в учебнике, модель записала в обосновании `2 bar(i)/3!` вместо `2πi/3!`. Автоматическая Q этого не учитывает.
